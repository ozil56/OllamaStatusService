Ollama 状态服务 1.2.4 · 并发 pull/push 修复验证（2026-10-16）

原因：原实现把 /api/pull、/api/push 放入单执行位调度器，默认等候 15 秒，第二个下载可能返回 queue_wait_timeout。
修复：模型传输并发透传，保留流式进度与后端错误，移除推理排队/读取/执行时限；其他调度规则保持不变。
传输在 inflight_model_transfers/model_transfers 中单独统计，state=busy 防止维护误判空闲；can_start_now 反映推理执行位是否可用。
取消传输会关闭上游连接，不形成推理 unknown 记录；状态统计仅覆盖当前 HTTP 连接，后端下载取消与续传仍由 Ollama 决定。

验证结果：
1. 新增 8 项真实 HTTP 专项测试：双 pull、直连与代理入口并发、流式进度、长时间无输出、下载与推理双向并发、断线清理、收到响应头前取消、push、非流式及错误透传。
2. 并发测试先在旧源码上复现失败，再在修复源码上通过。
3. 原有 60 项 Python 测试通过；修正双栈测试等待条件，使其等待请求实际开始执行后再判断 active_origin。
4. 10 种隔离安装升级场景通过。
5. 两个本机官方 ollama.exe pull 进程同时连接临时测试网关，确认后端同时收到两个传输，两进程均退出 0 并返回 success。

测试均使用临时端口与模拟后端，没有下载真实模型，也没有改动已安装的生产服务。1.2.4 公开发行包另含更新的版本说明与下载链接；应用代码与已验证的本地修复包相同。

本次修改
  新增 proxy_listen_host=127.0.0.1、proxy_listen_port=11436，旧配置缺少字段时自动使用默认值。
  在同一个 Uvicorn 服务实例中绑定直连和代理入口，共用一次应用生命周期、执行槽、队列、容量、状态和 SQLite 任务库。
  代理入口依据接受连接的 Socket 本地端口固定判为 remote，不依赖 HTTP Host 或任意客户端请求头。
  11434 直连入口保留回环及同地址判定；本机等待优先，两类各自 FIFO，不打断当前运行请求。
  代理入口默认仅 IPv4 回环，不自动增加 11436 防火墙开放规则；可配置指定 IPv4/IPv6 地址或双栈。
  任一入口绑定失败即停止启动，并释放已经建立的监听；保留 IPv6 zone/scope。
  /help 与 /healthz 增加 request_origin，可在不执行推理的情况下确认入口分类。

部署边界
  本轮构建测试不修改本机已安装的生产服务、实际 FRP 或防火墙；生产服务仍需运行新安装器升级。
  所有推理测试使用动态临时端口和模拟后端，不消耗真实模型/GPU，不打断其他任务。
  尚未在其他服务器上实际升级或从其公网 FRP 入口完成端到端验收。
  只升级程序而继续把 FRP 回源到 11434，仍会把本机回环转发误判为 local；必须同时迁移回源。
  默认 11436 仅监听 127.0.0.1；异机代理需显式配置网卡监听和按来源限制的防火墙规则。
  非抢占保证适用于正常调度；安装升级、停止服务及重启 FRP 应在任务全部完成后的维护时段进行。
