# Ollama 官方程序更新

OSS 1.5.0 在托盘加入 **检查更新／升级 Ollama**。检查使用 `ollama/ollama` 官方 GitHub 最新稳定发行版；启动约 15 秒后检查，此后每 6 小时检查，同一版本自动通知一次。网络失败后 30 分钟重试，不会把检查失败显示成“已是最新版”。安装始终由用户点击升级并确认 Windows UAC 后开始。

## 正常升级

1. 点击托盘菜单，查看当前版本、最新稳定版本和下载大小。
2. 点击“升级 Ollama”。后台先核实状态，再下载官方安装包；下载过程中 OSS 继续服务。
3. 检查官方发行资产的 SHA256、文件大小和有效的 Ollama Inc. Authenticode 签名。任一校验失败都不停止服务。
4. 临时阻止新任务进入，再检查正在执行和排队的推理、上传/下载、服务器托管模型任务、未知结果以及仍在接收内容的 HTTP 操作。只要有未完成任务就退出本次升级、重新接单；不强制取消，也不默默安排稍后停服。下载好的安装包可在重试时复用，但仍重新验证。
5. 空闲时备份 OSS 注册、配置、两个服务 XML、启动方式及模型清单；停止网关和后端，暂时禁用开机启动与看门狗。
6. 用原 Windows 账户在原目录执行官方安装器，禁止自动重启。安装器派生的官方应用使用临时回环端口；结束后关闭该安装目录内的官方后台，并清理官方自启动，恢复 OSS 接管。
7. 验证后端和网关都可访问、实际 Ollama 版本符合目标、模型名称和摘要完全一致、OSS 配置文件哈希未改变。通过后恢复原服务启动方式与看门狗，并重新接单。

模型目录不移动、不删除、不重新下载。后端 XML 中的模型路径与环境变量、OSS 的 `config.json`、任务数据库和用户数据不被更新器改写。安装包不得用于降级；如果模型目录位于 Ollama 程序目录内、发现其他 Ollama 实例或使用了不同 Windows 账户，更新会被拒绝。

## 失败与恢复

关闭进度窗口或退出托盘不会取消已经启动的协调程序。可再次从托盘打开查看进度。

安装失败会尝试恢复可用的旧版或新版后端，并验证原模型和配置。恢复成功仍明确报告升级失败；不把恢复服务当作升级成功。如果恢复验证失败，保留维护标记和备份，阻止新任务进入。修复原因后点击 **恢复上次升级**。

如果官方安装器返回需要重启，服务保持禁用；Windows 重启后再点击恢复。上次协调程序异常退出时，可通过同一入口恢复。不会在安装器仍运行时抢先接管。此流程不承诺自动回滚 Ollama 的全部程序文件；如果安装器已破坏原程序，须用同版本官方安装包修复原目录后再恢复。

状态：`%ProgramData%\OllamaStatusService\updater\status.json`。

日志：`%ProgramData%\OllamaStatusService\logs\ollama-update-*.log`。

备份与官方安装日志：`%ProgramData%\OllamaStatusService\updater\backups\ollama-update-*`。

## 接单保护与范围

维护标记位于 `%ProgramData%\OllamaStatusService\updater\maintenance.lock`，只能由本地管理员写入，没有远程 HTTP 升级/停服接口。维护期间新的工作请求返回 HTTP 503、`X-Ollama-Forwarded: false` 和 `forwarded: false`；状态、版本、模型列表和管理界面仍可读取。

`/status.ollama_update` 提供 `protocol=1`、`maintenance`、`safe_to_stop`、仍在进行的 HTTP 操作数、未知模型任务数和模型后台执行器数。即便请求内容尚未上传完成，也不会误判成可以停服。维护标记建立前已受理的工作继续执行，直到自然完成。

保护针对 OSS 受理的任务。应保持 Ollama 后端端口仅供 OSS 使用，不要绕过 OSS 直接向 11435 提交任务。发现其他 Ollama 程序实例会拒绝升级，因为官方安装器按进程名称关闭程序。

本功能需要运行新版后台。仅替换托盘 EXE，旧后台不能提供安全停服确认，更新器会拒绝执行。安装 OSS 1.6.1 自身时仍需安排空闲时段；这与安装完成后由托盘升级官方 Ollama 是两个不同的流程。

## 验证

`tests/ollama_update_guard.py` 使用真实 HTTP、临时端口和模拟后端，检查两类入口的维护拒绝、运行/排队推理不被取消、下载不中断、暂停任务保留、上传请求计数和未知模型任务阻止升级。

`tests/ollama_update_checks.ps1` 替换网络、服务和安装器边界，检查忙碌与请求竞争、签名拒绝、成功顺序、安装失败恢复、恢复失败保留维护标记、需要重启及配置不变。测试不运行真实 Ollama 安装器。

1.6.1 修复升级完成后的托盘提示：手动检查、升级完成和本机版本刷新都会更新同一菜单状态；当前版本已达到最新时显示“检查 Ollama 更新（当前版本）”，不再重复建议安装相同版本。启动、停止、恢复及官方升级通过无控制台的图形工作进程执行 PowerShell，保留 UAC 和必要的确认窗口。
